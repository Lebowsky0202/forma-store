# FORMA: публичная демоверсия для портфолио

В корне подготовлен `render.yaml`: один Node.js web service отдаёт API и собранный React-интерфейс с общего HTTPS-адреса. PostgreSQL хранит пользователей и заказы; отдельный persistent disk хранит изображения `/uploads`. Публичный магазин в Render пока не создан. Коммит этих файлов не запускает хостинг и не создаёт расходы.

## Ресурсы и стоимость

Blueprint намеренно использует **платные** ресурсы:

| Ресурс | Конфигурация |
| --- | --- |
| Node web service | `0.5c-512mb`, 1 экземпляр, Frankfurt |
| Изображения | persistent disk, 1 GB, `/var/data/forma-uploads` |
| PostgreSQL 18 | `0.1c-256mb`, 1 GB storage, Frankfurt |

Web service, вычисления PostgreSQL и диски оплачиваются; дополнительные расходы возможны при превышении включённых лимитов. Итоговую сумму нужно проверить в форме создания Blueprint и на [странице цен Render](https://render.com/pricing) до подтверждения. Платные ресурсы не были заказаны. Указанные размеры — начальная конфигурация для небольшого демо, без результатов нагрузочного тестирования.

Названия планов сверены с [актуальной таблицей Compute Plans](https://render.com/docs/compute-plans): `0.5c-512mb` соответствует прежнему Starter. Диск подключается к платному сервису; без него загруженные изображения пропадут после пересоздания файловой системы. [Документация Persistent Disks](https://render.com/docs/disks)

Бесплатный PostgreSQL Render имеет ограниченный срок жизни, а бесплатный web service засыпает и не поддерживает persistent disk. Поэтому этот Blueprint не выдаётся за бесплатное постоянное размещение. [Ограничения бесплатных ресурсов](https://render.com/docs/free)

## Публикация

1. Войти в Render и подключить GitHub с доступом к `Lebowsky0202/forma-store`.
2. Выбрать **New → Blueprint**, нужный репозиторий и ветку с этим `render.yaml`. Root directory оставить пустым: npm workspaces собираются из корня.
3. Проверить конфигурацию, доступность тарифов и итоговую стоимость. Подтвердить создание только после согласования расходов владельцем аккаунта.
4. Render создаст PostgreSQL, диск и web service, сгенерирует отдельные случайные `JWT_SECRET`, `SEED_ADMIN_PASSWORD`, `SEED_USER_PASSWORD` и подставит внутренний `DATABASE_URL`. В репозитории значений секретов нет.
5. Дождаться успешного `/api/health` и открыть выданный Render HTTPS-адрес. Собственный домен для первого показа не требуется.
6. Проверить каталог и изображения, регистрацию тестового пользователя, заказ и отмену, затем заменить ссылку на демоверсию в портфолио фактическим проверенным адресом.

Параметры Blueprint описаны в [официальном справочнике](https://render.com/docs/blueprint-spec). Автоматический deploy после каждого коммита выключен (`autoDeployTrigger: off`), чтобы изменения портфолио не перезапускали магазин. Новую версию можно выпустить вручную через **Manual Deploy**. Blueprint sync и первоначальное создание управляются отдельно от автоматических deploy.

## Что делают команды

`node scripts/render-build.mjs` устанавливает зависимости frontend/backend из lock-файла, включая инструменты сборки; генерирует Prisma Client и собирает backend и frontend. Node.js задан через `NODE_VERSION` в пределах ветки 22.22.x. [Выбор версии Node в Render](https://render.com/docs/node-version)

`node scripts/render-start.mjs` устанавливает абсолютный `FRONTEND_DIR`, запускает `prisma migrate deploy`, затем идемпотентный seed и сервер. Повторный seed сохраняет существующие пароли, товары, заказы и остатки; недостающие файлы начальных изображений копируются с запретом перезаписи. При ошибке миграции или seed сервер не начинает принимать запросы.

Seed запускается при старте, когда доступен persistent disk. В Render диск недоступен на этапах build и pre-deploy. Сервис с диском нельзя масштабировать на несколько экземпляров; во время deploy есть короткий перерыв. [Ограничения диска](https://render.com/docs/disks#disk-limitations-and-considerations)

`CORS_ORIGIN` берётся из `RENDER_EXTERNAL_URL`, который предоставляет Render. API, фронтенд и refresh-cookie используют один origin; production-cookie остаётся `Secure`, `HttpOnly`, с прежними правилами ротации и проверки ролей. `TRUST_PROXY=1` учитывает HTTPS-прокси Render. [Переменные Render](https://render.com/docs/environment-variables)

Для собственного домена нужно настроить его в Render и явно задать `CORS_ORIGIN=https://ваш-домен` без пути. Используйте этот адрес как основной: изменение origin не разрешает обращения с произвольных дополнительных доменов.

## Демонстрационный режим и админка

`VITE_DEMO_MODE=true` — переменная **времени сборки**. Она включает заметный баннер, предупреждение перед оформлением и явное подтверждение тестового заказа. После изменения значения нужна новая сборка. Для локального Vite она читается из корневого `.env`; в `.env.example` по умолчанию `false`, чтобы сохранить обычную локальную витрину.

Демо использует настоящую базу и обычную бизнес-логику: заказы сохраняются, остатки резервируются, отмена возвращает товар. Это не режим обхода авторизации. Доставка, списание денег и уведомления не подключены. Посетителям предлагается использовать вымышленные данные. Автоматического удаления регистраций/заказов и сброса остатков нет: владелец периодически проверяет демо через обычную админ-панель.

Владелец входит через `/login?redirect=/admin` с email `admin@forma.local` и случайным `SEED_ADMIN_PASSWORD` из **Environment** своего сервиса Render. Эти значения нельзя размещать на сайте портфолио, в README или публичном демодоступе. Демонстрацию админки клиентам можно показывать скриншотами или лично. Публичного аккаунта администратора и специальной роли с ограниченным доступом не добавлено. Посетители могут самостоятельно зарегистрировать тестовый аккаунт покупателя.

Повторное изменение `SEED_ADMIN_PASSWORD` в Render **не меняет пароль уже созданного администратора**: seed сохраняет существующую запись. Для смены пароля необходима отдельная контролируемая процедура обновления хеша; не удаляйте пользователя или базу ради смены пароля.

## Проверки и ограничения

Локально 13 сентября 2026 повторно выполнены:

- TypeScript typecheck и production build с `VITE_DEMO_MODE=true`.
- 21 backend-тест: 14 интеграционных на настоящем PostgreSQL 18.4, 4 проверки валидации и 3 проверки раздачи SPA. Проверены deep links, отсутствие HTML-подмены ошибок `/api`, `/uploads`, `/assets`, `.env` и не-HTML запросов.
- `render-start.mjs` запустил migrations/seed и production-сервер на `localhost:4001`; existing records сохранены.
- В Chrome: каталог и баннер на 320/1440 px без горизонтального переполнения; регистрация, тестовый checkout, подтверждение, перезагрузка страницы с восстановлением сессии и отмена; `Secure`/`HttpOnly` refresh-cookie; отказ покупателю в доступе к админке и успешный вход владельца со списком товаров. Ошибок JavaScript не обнаружено. Проверочный аккаунт и его заказы удалены, остатки восстановлены.

Отдельная повторная browser-проверка демо сохранена в `.local/demo-verification/`: скрипт, JSON-отчёт и 6 снимков. Подтверждены 9 проверок, один origin `localhost:4001` для API и интерфейса, изменение остатка `9 → 8 → 9` после заказа и отмены. Удалены тестовый аккаунт, его заказы и временная административная сессия. Локальный demo-сервер после проверки остановлен.

Render Blueprint не применялся в облаке: Linux-сборка из чистого checkout, реальный HTTPS, подключение Render PostgreSQL и сохранность диска после redeploy требуют проверки после создания ресурсов. Docker-конфигурация сохранена; её фактический запуск здесь не проверен. Регулярные резервные копии и восстановление требуют отдельной проверки в выбранном хостинге. Магазин подготовлен для демонстрации портфолио, коммерческие платежи и логистика не подключены.
